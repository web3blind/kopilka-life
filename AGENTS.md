# AGENTS.md — Копилка жизни / Life Harbor

## Назначение и продуктовые границы

VK Mini App, Telegram Mini App, сайт и бот с общей серверной учётной записью. Человек замечает конкретные действия, поддерживающие жизнь: сон, движение, радость, благодарность, дела, мечты, отдых и честные итоги.

- **ЖИЗНЬ** — наглядный след заботы о себе, не KPI, рейтинг человека, доходность или оценка его ценности.
- Мягкость важнее дисциплины: никаких наказаний за пропуск, давления, центрального streak или «ты провалился». Тяжёлый день — валидная запись.
- Базовое действие занимает один клик; заметка необязательна. Не превращать продукт в обязательный дневник или общий habit tracker.
- Договор заботы — мягкая недельная цель, подарок себе и честный итог. Денежные поля лишь фиксируют намерение: приложение не принимает и не переводит деньги, не хранит ключи и не инициирует crypto transfers.
- Не добавлять реальные платежи, wallet custody, азартные механики или AI-рекомендации без отдельного согласования. Подсказки не являются медицинскими рекомендациями.
- Практики конкретны и коротки, без отчётности и морализаторства. «Достаточно на сегодня» — возможный тон статуса, не категория действия.
- Писать тепло и коротко: «Можно отметить одну маленькую вещь», «Цель была слишком сложной — это полезный вывод». Не использовать стыд, сравнение и «индекс счастья».
- Согласованный ИИ-помощник — отдельная седьмая вкладка, ручной opt-in владельца за последние 1–30 календарных дней, включая сегодня в его timezone. Одна тема: выжимка либо выжимка с до трёх бережных рекомендаций. Общий durable лимит — один запрос за скользящие 168 часов для всех тем/периодов; смена языка/timezone, удаление текста и merge не сбрасывают лимит. Пустой период не отправлять и не расходовать слот. Заметки — недоверенные данные, не инструкции; не логировать и не выводить в публичный профиль. Не включать фоновые генерации, платный fallback или повторную отправку после неопределённого результата. Платный режим API — только по отдельному явному AI_WEEKLY_PAID_ENABLED; ключ сам по себе не даёт разрешения расходов, price ceilings обязательны. Баллы и обычный недельный разбор независимы от ИИ. Шаблон отдыха остаётся редактируемой необязательной опорой, не новым трекером или оценкой человека.

## Архитектура и карта кода

Один лёгкий Node.js/Express 5 процесс, CommonJS, SQLite через better-sqlite3. Vanilla HTML/CSS/JS без React/Next/Vue, SSR и тяжёлой frontend-сборки. Telegram — webhook, не polling. Не увеличивать число процессов без пересмотра scheduler, webhook lease и in-memory rate limits.

- `src/server.js` — HTTP entrypoint: региональная HTML-оболочка, static, API, webhook, запуск scheduler. Запускать из корня: `public/` и `migrations/` разрешаются относительно cwd.
- `src/config.js` — env-конфигурация и production validation; `src/db.js` — WAL, foreign keys, busy timeout, транзакционные миграции и реестр `_migrations`.
- `src/routes/api.js`, `src/routes/webhook.js` — канонические HTTP routes; `src/auth/` — platform proof, app sessions и OAuth handoff.
- `src/services/` — записи, договоры, напоминания, артефакты, рефералы, полезные действия, профили, story PNG, вход и объединение аккаунтов.
- `public/index.html`, `public/app.js`, `public/styles.css` — клиент. Семь вкладок: Сегодня, История, Договор, ИИ-помощник, Настройки, Полезное, Профиль. ИИ не размещается внутри Истории.
- `src/i18n.js` и `public/i18n.js` — серверный и клиентский RU/EN. Изменение интерфейса проверять в обоих языках.
- Источник категорий и баллов — `ENTRY_TYPES` / `ENTRY_POINTS` в `entriesService.js`; начисления за договоры — `contractsService.js`; подсказки и практики — `productContentService.js`. Не дублировать расходящиеся таблицы баллов в документации/frontend.
- `tests/` — Node, HTTP и connected browser regression tests; `tests/fixtures/` — тестовые провайдеры, никогда не production preload.
- `PLAN.md` хранит согласованный план; текущие поправки пользователя имеют приоритет. Сохранять существующую незавершённую работу и не расширять задачу соседними улучшениями.

## Запуск и проверки

- Установка по lockfile: `npm ci`; запуск: `npm start`; development: `npm run dev`.
- `npm run init-db` и запуск приложения применяют отсутствующие миграции — это не read-only команды. Для локального запуска заранее задавать отдельный `DB_PATH`.
- `src/config.js` вызывает `dotenv.config()` и читает `.env` из cwd. Один `DOTENV_CONFIG_PATH=/dev/null` не гарантирует изоляцию: явно задавать безопасные env либо использовать каталог без рабочего `.env`. Не использовать реальные provider credentials в QA; выключать scheduler.
- Полный Node gate: `npm test`. Проверять актуальный список `scripts.test` в `package.json`; дополнительные файлы вне списка запускать явно. При добавлении обязательной регрессии обновлять список.
- Основной browser gate: `python3 tests/run-browser-qa.py`.
- Региональный browser gate: `python3 tests/run-browser-qa.py region-browser-qa.py`.
- Матрица направлений e-mail/Google/Telegram/VK: `KOPILKA_QA_PORT=3157 python3 tests/run-browser-qa.py link-matrix-browser-qa.py`. Она запускается отдельно от стандартных browser suites.
- Browser QA требует Python Playwright и доступного Chromium CDP; endpoint задаётся `KOPILKA_QA_CDP_URL`. Использовать изолированные contexts, не закрывать чужие вкладки/общий браузерный процесс; не запускать конфликтующие suites параллельно на одинаковых портах.
- Runner создаёт временную SQLite и останавливает свой Node server в `finally`. После QA проверять завершение собственных процессов; чужие процессы не останавливать.
- Local provider fixtures заменяют доставку/проверку провайдера, но не app auth/merge routes. Они не доказывают live provider login.
- После auth/UI изменений нужны connected browser checks, не только Node. Проверять `node --check` для изменённых JS и `git diff --check`; Python QA — через `python3 -m py_compile`.

## Вход и identity: обязательные инварианты

- `initDataUnsafe`, query ID и неподписанный platform context не являются доказательством личности. Telegram initData и VK launch proof проверяются backend.
- Текущий подписанный Mini App launch определяет пользователя раньше cached bearer. Нельзя читать частные данные A до проверки запуска B. Сайт без platform context использует отдельную website session.
- Валидный Telegram/VK launch входит напрямую; OAuth fallback запускается только явно. Восстановление истёкшей сессии не должно подменять account или терять черновик.
- Региональная политика задаётся `countryService.js`, `landingHtmlService.js` и API-gates; RU и неизвестная страна используют регион RU. Не обходить website auth gating через скрытые кнопки или direct API. Proxy/IP trust должен соответствовать цепочке reverse proxy.
- E-mail/Google identities хранятся в `login_identities`, платформенные — в `users`. Не объединять произвольные совпадающие e-mail автоматически; существующее правило подтверждённого Gmail и нормализации aliases проверяется `google-auth.test.js`.
- Привязка способов входа находится в авторизованном «Профиле», не дублируется в «Настройках» и не раскрывается на анонимном экране.
- Google intent хранит revision и hash инициирующей сессии. Проверки при authorize/callback, browser binding, одноразовый state, PKCE/nonce и проверка revision перед записью identity обязательны.
- Telegram cross-context linking (`telegramLinkService.js`) требует intent, подписанный claim с явным согласием и завершение исходной сессией. Один переданный launch URL не разрешает привязку.
- VK OAuth callback для link возвращает verified proof; изменение аккаунта выполняет authenticated `finalize-link` исходной сессии. Handoff проверяет точный origin и ожидаемое окно; bearer нельзя помещать в URL.
- Отвязка e-mail/Google не должна удалять данные или последний пригодный способ входа: `loginIdentityService.js`, `unlink-login.test.js`.

## Объединение и сохранность данных

- VK merge — `accountMergeService.js`; e-mail/Google/Telegram offers — `identityMergeService.js`; перенос истории/рефералов — `mergeRecords.js`. Правила сохранности проверять в обоих merge engines.
- Занятая identity с данными требует verified proof, preview и явного подтверждения. Cancel не меняет записи. Offer привязан к инициирующей сессии; confirmation повторно строит preview внутри транзакции.
- Конфликты identities, активных договоров, рефералов, напоминаний и несовместимых metadata блокируют merge без частичных записей. Нельзя молча терять включённые настройки напоминаний retiring account.
- Сохранять заметки, баллы, договоры, артефакты, referral aliases и права доставки. Независимые исторические записи одинакового day/type остаются раздельными; не дедуплицировать их ценой потери истории.
- После merge старые сессии обеих сторон недействительны, survivor получает новую сессию. `src/auth/session.js` проверяет `session_revision`; legacy token без revision совместим только с revision 0.
- Обычное новое быстрое действие по-прежнему ограничено одним типом за локальную дату пользователя (`createEntry`). Сохранённые merge-дубликаты не разрешают повторное новое действие.

## API, время, миграции и доставка

- Каноническая схема — `migrations/*.sql`, маршруты — `src/routes/`; не опираться на старые draft-списки API/таблиц.
- SQL миграции и отметка `_migrations` применяются одной транзакцией. Уже применённые миграции не переписывать; изменения схемы оформлять следующей миграцией.
- 017 — Google intents; 018 — session-bound merge offers и referral aliases; 019 — Telegram link intents; 020 — session revision и удаление уникального индекса дневных entries.
- После 020 нельзя вслепую возвращать старый код или уникальный индекс: объединённая история законно содержит одинаковые day/type. Rollback требует проверки совместимости и не должен затирать новые записи старой БД.
- History user-scoped; редактирование заметок/удаление разрешены только для обычных actions. Новый note ограничен 2000 символами без silent truncation; существующую более длинную заметку можно сохранить без дальнейшего увеличения. Системные начисления защищены.
- Даты вычисляются в timezone пользователя (`src/time.js`); внутренняя неделя и публичные последние семь календарных дней — разные окна.
- Публичный профиль и story PNG не должны раскрывать private notes. Картина дня и временный URL её PNG (`daySceneStoryService.js`) — отдельный сценарий, не замена публичной карточки.
- Scheduler по умолчанию выполняется раз в минуту без наложения ticks; сохранять retry/backoff и защиту от повторной доставки при неоднозначном ответе провайдера.
- Webhook требует secret, durable дедупликацию update ID, processing lease и fencing попыток. Не ослаблять их при изменении обработчиков. Ошибки логировать диагностично, но без токенов, credentials и личных payload.

## Accessibility и интерфейс

- Semantic HTML, настоящие buttons/forms, labels, логичные заголовки и порядок фокуса. Не передавать смысл только цветом/иконками; графические данные дублировать текстом, избегать drag/drop.
- Важные статусы доступны screen reader. Preview merge имеет заголовок с управлением фокусом и отдельные кнопки подтверждения/отмены; не добавлять произвольный autofocus.
- Проверять клавиатуру, возврат фокуса, browser Back, 200% текста и отсутствие перекрытия controls фиксированной навигацией. Все семь вкладок видимы одновременно без прокрутки самой панели; подписи не обрезаются, targets не меньше 44×44 CSS px. Длинные footer links должны быть доступны при прокрутке, не обязательно одновременно в одном viewport.
- Геометрия навигации: `python3 tests/nav-layout-browser-qa.py`; необязательное сравнение с шестью вкладками: `python3 tests/nav-layout-browser-qa.py --baseline 5c7e405` (read-only `git show`, без checkout). Реальные переходы мышью/клавиатурой/касанием и clearance фокуса: `python3 tests/run-browser-qa.py ai-weekly-browser-qa.py`.
- Юридические документы открываются внутри существующего Mini App reader без потери вкладки, draft, scroll и identity.
- Сохранённое действие и неудача последующего refresh — разные результаты: retry не создаёт дубль. Сохранять раздельные черновики и несохранённые настройки.
- Story/share открывает нативный редактор либо доступный fallback. Публикацию подтверждает пользователь; отмена не считается ошибкой или успешной публикацией.

## Конфигурация и безопасная выкладка

- Секреты — только в непубликуемой конфигурации; `.env.example` — безопасные примеры. Не записывать в AGENTS.md приватные адреса инфраструктуры, аккаунты, ID пользователей, credentials, пути бэкапов или значения env.
- API проверяет identity и ownership сервером; не логировать bearer, полный initData, OTP и OAuth secrets. Dev auth/demo cleanup выключены в production.
- `scripts/deploy-life.sh --preflight` — read-only gate, не автоматический deploy. `npm run webhook:info` читает состояние; `webhook:set`/`webhook:clear` меняют внешнюю систему и не нужны при каждом обновлении кода.
- Перед разрешённой выкладкой установить live cwd/DB/process по фактам. Не заменять production `.env`, `data/`, медиа и dirty-код широким sync/reset; не хранить конкретные process IDs и серверные пути здесь.
- SQLite backup — online API либо согласованный stopped snapshot с WAL/SHM. Проверить зашифрованный backup вне webroot, доступность ключа вне сервера, расшифровку, integrity/foreign keys и сохранность данных при миграции восстановленной копии.
- Загружать только проверенный список файлов, перезапускать только целевой процесс; сверять hashes, health, DB continuity и отсутствие изменений соседей. Не накатывать старую БД поверх новых пользовательских записей.
